# KoK

一个 macOS 状态栏效率工具，四件事：

- **划词翻译**：选中任意文本，按快捷键在浮动面板中看译文；
- **快速问答**：按快捷键弹出对话面板，直接打字问问题，流式返回。

两者共用同一套引擎配置与 API Key。支持多引擎（DeepL / Gemini / 任意 OpenAI 兼容服务）、
翻译历史、全局与单引擎自定义提示词。

## 功能

- **多引擎**：数据驱动的引擎配置，可自由添加 / 编辑 / 删除引擎
  - `DeepL` 专用协议（仅翻译）
  - `Gemini`（Google Generative Language）
  - `OpenAI 兼容`：OpenAI、腾讯云 Token Plan、DeepSeek、通义千问、Moonshot、智谱等
- **批量添加**：内置腾讯云 / OpenAI / DeepSeek / 智谱 / Moonshot 预设模板
- **提示词**：翻译与对话各自独立的系统提示词；翻译提示词支持 `{{TARGET_LANG}}` 变量，留空则回退到内置默认
- **体验**：面板可拖拽调整大小、`Esc` 关闭、复制反馈、失败重试、切换引擎自动重译
- **历史记录**：保留翻译历史
- **对话 + 语音**：同一个键——**点按**打开对话面板，**按住**说话（连同选中的文本 / 图片一起发给模型）
- **框选截图**：按快捷键框选屏幕区域，直接作为上下文（对任何 App 都成立）
- **生图**：直接说「生成/画一张…」自动路由到生图（无需点按钮），上下文里的图片自动当参考图；
  也可以点 ✨ 手动进入生图模式。出图后可复制/保存/打开
- **状态栏**：左键打开对话，右键菜单可打开设置 / 开关机自启动 / 退出
- **开机自启动**：基于 `SMAppService`

## 快捷键

| 动作 | 默认键 | 说明 |
|---|---|---|
| 翻译 | `⌥D` | 读取当前选中文本（需要「辅助功能」权限） |
| 对话 / 语音 | `⌘1` | **点按**打开对话面板；**按住**录音，松开后连同选中内容一起发送 |
| 框选截图 | `⌥C` | 框选屏幕区域作为上下文（`⌥S`/`⌥A` 被 iShot 占用，故避开） |

两者都可在「设置 ▸ 通用」里重新录制。

> ⚠️ 全局热键是**系统级**的：注册 `⌘1` 后，浏览器 / Xcode 等应用自身的 `⌘1`
> （通常是「切到第 1 个标签页」）会被 KoK 抢走。介意的话换成 `⌃1`、`⌘⇧1` 这类
> 应用内不常用的组合。

### ⚠️ 快捷键冲突（重要）

macOS 的 `RegisterEventHotKey` 在组合被别的 App 占用时**不会返回错误**，事件会静默地
被先注册方吃掉，表现就是「按了完全没反应」。

已知 **iShot** 会占用 `⌥A`、`⌥B`、`⌥D`、`⌥E`、`⌥F`、`⌥G`、`⌥H`、`⌥O`、`⌥P`、`⌥Q`、
`⌥R`、`⌥S`、`⌥T`、`⌥W`、`⌥X`、`⌥Z`。所以默认键避开了这些组合。

设置页每个快捷键旁边都有 **「测试」** 按钮：点一下，然后按下该快捷键——

- 显示 **生效** → 组合可用；
- 显示 **未收到，可能被其它 App 占用** → 换一个组合重试。

> 换个组合后建议顺手在占用方 App 里确认一下，避免两边抢同一个键。

## 构建与安装

### 用 Xcode

1. 打开 `KoK.xcodeproj`
2. 选择 scheme `KoK`，目标 `My Mac`
3. `Product ▸ Archive`（会产出 universal 二进制：`arm64` + `x86_64`）
4. 在 Organizer 中 `Distribute App ▸ Copy App`，把 `KoK.app` 拖到 `/Applications`

### 命令行

```bash
xcodebuild -project KoK.xcodeproj -scheme KoK \
  -configuration Release -derivedDataPath build/dd \
  ARCHS="arm64 x86_64" ONLY_ACTIVE_ARCH=NO build

# 产物：build/dd/Build/Products/Release/KoK.app
```

安装（会先退出正在运行的实例）：

```bash
osascript -e 'quit app "KoK"' 2>/dev/null
rm -rf /Applications/KoK.app
cp -R build/dd/Build/Products/Release/KoK.app /Applications/
open /Applications/KoK.app
```

## API Key 配置

**源码与仓库中不包含任何真实密钥。** 每个引擎的 Key 按以下顺序解析（见
`KoK/TranslationService.swift` 的 `EngineConfig.resolvedAPIKey`）：

1. 「设置」面板中为该引擎保存的 Key（保存到用户偏好 `Translator-App.KoK.plist`）；
2. 环境变量 `KOK_API_KEY_<引擎名>`：引擎名转大写，非字母数字字符替换为下划线。

例如：

| 引擎名 | 环境变量 |
|---|---|
| `Qwen` | `KOK_API_KEY_QWEN` |
| `DeepL` | `KOK_API_KEY_DEEPL` |
| `我的通义千问` | `KOK_API_KEY_我的通义千问` |

> 环境变量方式主要用于命令行 / Xcode scheme 中调试。从 Finder 启动的 App 读取不到 shell
> 环境变量，这种情况下请在「设置」面板里填写。

若两者都没有配置，翻译时会提示「请在设置中填入 <引擎名> 的 API Key」。

### 安全须知

- 不要把真实 Key 写进源码、`Info.plist` 或任何会被提交的文件。
- 建议提交前自查：

  ```bash
  git grep -nE 'sk-[A-Za-z0-9]{16,}|AIza[A-Za-z0-9_-]{20,}|apiKey: "[^"]+"'
  ```

- 用户手动填写的 Key 目前以**明文**保存在
  `~/Library/Preferences/Translator-App.KoK.plist`（文件权限 `600`）。如需更强保护，
 可改为存入 Keychain。

## 引擎配置：服务商 → 模型

配置分两层，和 Cherry Studio / ChatBox 等产品的做法一致：

```
服务商（Provider）                    ← API Key / 接口地址在这一层，只填一次
  └─ 模型（ProviderModel）           ← 勾选哪些模型可用
```

- **API Key 是服务商级的**：腾讯云下面挂 11 个模型，也只需要填一把 Key。
  旧版是「一个引擎 = 一套地址 + Key + 模型」，11 个模型就要填 11 遍。
- **协议 / 接口地址收进「高级」**：用户想的是"我要用 DeepSeek"，不是"我要配一个 OpenAI 兼容端点"。
- **「译 / 聊」两个小标签**直接标明该模型用于哪个用途，取代了原先「启用开关 + 绿点 + 设为默认 + 蓝勾」
  四套重叠的状态。
- **写透式自动保存**，没有「保存」按钮。
- **「测试」按钮**：填完 Key 立刻验证连通性，并显示往返耗时，不用先存再跑去翻译一次。
- **「获取模型」**：直接调服务商的模型列表接口自动发现可用模型，免去去文档里抄模型 ID。
- **备注与官网链接**：备注显示在左侧列表（如「公司账号 · 10 月到期」），官网地址一键打开控制台查余额。
- **预设按类别分组**：国内服务商 / 国际服务商 / 聚合中转 / 专用协议 / 自定义。

### 获取模型（自动发现）

模型 ID 是最容易抄错的东西（`hunyuan-2.0-instruct` 差一个字符就 404），所以提供两个入口：

- **添加服务商时**：在「模型」一栏点「获取模型」；
- **已有服务商**：详情页「从服务商获取」，勾选后追加。

实现要点（`ModelDiscovery.swift`）：

- 我们存的是**完整 endpoint**，需要反推出模型列表地址：
  `.../v1/chat/completions` → `.../v1/models`；Gemini 则把 `/{{MODEL}}:generateContent`
  换成 `.../v1beta/models?key=...`。
- 失败按状态码给**可操作的提示**，而不是抛原始报错：

  | 返回 | 提示 |
  |---|---|
  | 401 / 403 | API Key 无效或没有权限 |
  | 404 / 405 | 该服务商不提供模型列表接口，请改用「手动添加」 |
  | 解析失败 | 返回内容无法解析（附前 120 字） |

- 结果会过滤掉明显不是对话模型的条目（`embedding` / `whisper` / `tts` / `dall-e` 等）。

> 做法参考了 [CC Switch](https://github.com/farion1231/cc-switch) 的「获取模型」与预设分组。

### 旧数据迁移

首次启动 2.2 时，会把旧版扁平的 `engine_configs` 自动合并成服务商结构：

- 按「接口地址 + API Key + 协议」分组，每组一个服务商，每条旧记录变成一个模型；
- `ProviderModel.id` 沿用旧的 `EngineConfig.id`，所以**已保存的翻译 / 对话选中项不会丢**；
- 原始 JSON 会备份到 `engine_configs_backup_v1`，需要回滚时把它的内容写回
  `engine_configs`、并删掉 `provider_store_v2` 即可。

## 翻译为什么是流式的

翻译请求本质上就是一次「对话」——system 放提示词、user 放原文——所以
`UnifiedTranslationService` 直接复用 `LLMClient`，只把「一次性请求」换成「流式请求」。

改造前两处叠加，让翻译明显比对话慢：

| 问题 | 说明 |
|---|---|
| 翻译**没有走流式** | 用 `URLSession.data(for:)` 等整段生成完才显示，首字延迟 = 整段生成时间 |
| **打字机效果是纯加出来的等待** | 响应已完整拿到后，再按 20ms/字（>100 字时 5ms/字）逐字显示，短文本反而多等 1–2 秒 |

现在译文由模型逐段返回、立即上屏，打字机已移除。实测（模拟每 150ms 吐一段的模型）：

```
流式    首字 86 ms  ／ 总耗时 851 ms
非流式  首字 763 ms（等于总耗时）
```

## 提示词变量（仅翻译）

「设置 ▸ 提示词」里的翻译提示词支持两个变量，翻译前会替换成实际语言名：

| 变量 | 中文原文时 | 英文原文时 |
|---|---|---|
| `{{TARGET_LANG}}` | `English` | `Simplified Chinese` |
| `{{SOURCE_LANG}}` | `Simplified Chinese` | `English` |

翻译方向沿用 App 自身的判断：原文含中文则译成英文，否则译成中文。

**写法容错**：`{{TARGET_LANG}}`、`{TARGET_LANG}`、`{{target_lang}}`、`{target_lang}`
四种都识别。这是刻意的——用户很自然会写单括号小写，若只认一种，变量会静默失效、
把 `{target_lang}` 原样发给模型。

**未知占位符会提示**：提示词里出现 KoK 不认识的 `{{FOO}}` 时，编辑框下方会直接标出来，
而不是让它悄悄失效。对话提示词不做变量替换，写了同样会提示。

## 性能实测

| 指标 | 实测值 |
|---|---|
| 安装包 | 6.0 MB |
| 空闲内存 | ~73 MB（两个面板预创建后；基线约 19 MB，对话面板 +20 MB、翻译面板 +1 MB） |
| 唤出面板（已预热） | 中位 4.6 ms |
| 首次创建对话面板 | 361 ms（仅在启动预热时发生，用户感知不到） |
| 翻译首字（流式） | 86 ms，对照非流式的 763 ms —— **快 8.9 倍** |
| 引擎配置加载 + 迁移 | < 10 ms |

> 面板采用「预创建 + 只做 Show/Hide」，并在启动完成 1.2s 后异步预热：
> 既不拖慢状态栏出现，也不会让第一次按快捷键卡 360ms。

## 快速问答的边界

为了保持轻量，以下都是**刻意不做**的：

- 对话**不落盘**：只存在内存里，关掉面板保留、点「新对话」清空、退出 App 即消失；
- 只保留最近 20 条消息（约 10 轮）作为上下文，避免 token 与费用失控；
- 不引入 Markdown / 网络 / 状态管理第三方库，代码块分块用约 60 行手写解析；
- 不支持多模态、文件上传、Agent 工具调用。

## 界面文案原则

设置界面只有三个 Tab，但很容易越写越啰嗦。约定：

1. **只留非显而易见的信息**。显而易见的操作说明（"点击按钮然后按下快捷键"）直接删掉。
2. **能一行就不要三行**。重要的长解释挪进 `.help()` tooltip，不占版面。
3. **不做重复声明**。"改动会自动保存"这类话不必说——没有保存按钮就是 macOS 设置面板的既定约定。
4. **不加冒号**。macOS 分组表单的标签不带 `：`。

判断标准：这句话删掉之后，用户会不会做错事？不会就删。

## 语音与截图

按住 **`⌘1`** 说话（点按则是打开对话面板），松开后：

```
① 抓选中内容：模拟 ⌘C，看剪贴板里是文本还是图片
② 录音转写：系统语音识别，边说边出字
③ 一起发给模型：选中内容作为上下文 + 你说的话作为指令
```

**有选中内容** → 选中即问（"这段代码帮我解释一下"）
**没有选中内容** → 你说的话直接当指令

### 为什么用系统识别而不是自带模型

用 `SFSpeechRecognizer`：零体积、零成本、中文可离线，且自带流式部分结果。
要塞本地 Whisper 就得几百 MB（而 Whisper Small 的中文字错率约 20%，本来就不可用），
和这个 App 的轻量前提直接冲突。实测本机 `zh-CN` / `en-US` 均支持离线识别。

> macOS 26 起 Apple 有准确率高得多的 `SpeechAnalyzer` / `SpeechTranscriber`，
> 且体积 <5 MB。等系统升级后可以平滑替换。

### 框选截图（⌥C）

**为什么需要它**：macOS 的辅助功能 API 只暴露「选中的文本」，**没有「选中的图片」**。
图片只能靠各 App 自己把位图写进剪贴板，所以 PDF 阅读器、微信、部分 Electron 应用里根本抓不到。

截图不依赖任何 App——像素由我们自己从屏幕上取，对任何场景都成立。
用的是系统的交互式截图（和 ⇧⌘4 同一套 UI），不自己造选择框。

典型用法：按 `⌥C` 框选 → 面板出现 `🖼 图片` chip → 再**按住 `⌘1`** 说「这是什么」→ 松开发送。

### 权限

| 权限 | 用途 |
|---|---|
| 辅助功能 | 模拟 ⌘C 抓选中内容（翻译也在用） |
| 麦克风 | 录音 |
| 语音识别 | 转写（本机完成，录音不出设备） |
| 屏幕录制 | 仅「框选截图」需要 |

首次使用会弹系统询问；也可以在「设置 ▸ 通用 ▸ 语音与截图」里点「去授权」。

### 图片体积

原图动辄几 MB，base64 之后会把首字延迟拖垮。所以统一缩放到**最长边 1024、JPEG 0.8**，
实测 2400×1800 的图压到 **12 KB**，比原图小两个数量级。

### 交互约定

几个反复权衡过的设计决定：

- **状态栏左键 = 打开对话**。菜单栏 App 的左键应该触发最高频动作，设置收进右键菜单。
- **对话与语音是同一个键**：点按打开、按住说话。按下时先以「不抢焦点」的方式弹出，
  180ms 内松手判为点按（补上焦点），过了阈值则开始录音；刚过阈值就松手且没识别到内容，
  按慢速点按处理。点按永远只聚焦、不关闭面板——关闭走 Esc / 点击外部 / ✕。
- **翻译面板有「追问」**：一键把原文 + 译文作为上下文带进对话面板，
  两个核心功能之间不再需要手动复制粘贴。
- **翻译方向可切换**：默认自动（含中文译英、其余译中），也可手动指定
  中文 / English / 日本語 / 한국어，切换立即重译并持久化。
- **面板定位跟鼠标、大小靠记忆**：弹出位置始终在鼠标附近（防出屏），
  但用户拖出来的对话面板大小会记住，重启不丢。
- **语音 / 截图先不抢焦点，拿到结果再露面**：否则模拟 ⌘C 会抓不到原 App 的选中内容，
  截图还会把面板自己截进去。

## 生图（✨）

**默认是自动路由**：在对话里直接说「生成/画/做一张…」或对着上下文里的参考图说
「根据这张图…」，模型会在回复开头输出一个标记块，App 剥掉标记、取其中的提示词自动生图，
图直接贴在同一条回复下面。判断和回复合并成同一次请求（零额外延迟），标记没打在开头也有兜底识别。

输入栏的 ✨ 按钮仍保留：手动切换生图模式时，输入即提示词，上下文里的图片（⌥C 截图 / 复制）
自动作为**参考图**。

- 自动路由生效的前提：设置 ▸ 通用 ▸ 生图已填 API Key（未配置时不会触发，避免空跑）。
- 自动生图用「自动」尺寸（模型按语义决定）；要指定尺寸就点 ✨ 在菜单里选。

- 接入的是**腾讯混元 Hy-Image-3.5-preview**（`tokenhub.tencentmaas.com` 的 wand 协议），
  配置在「设置 ▸ 通用 ▸ 生图」（接口地址 / API Key / 模型）。
- 尺寸可选：自动 / 1K 方形 / 2K 横竖 / 4K 三种（方形/横/竖），最高 4096×4096。
  预设全部用 **16 的倍数**——实测非 16 倍数的尺寸会被模型吸附（1920×1080 → 1920×1072）。
- 出图是同步调用（约 10–20 秒），响应里是 COS 签名 URL（有时效），
  所以 App 会**立刻把原图下载到本地**，再提供复制 / 保存 / 打开。
- 参考图以 base64 data URI 上送（实测支持），所以截图不需要公网 URL。

## 已知限制

- **「选中图片」没有系统 API**，只能靠模拟 ⌘C 读剪贴板。Preview / Safari / Finder 可用，
  但 PDF 阅读器、微信、部分 Electron 应用的行为不一致。**这类场景请改用 `⌥C` 框选截图。**
- 图片的剪贴板路径有个例外：按快捷键时剪贴板里已有图就会采用它（图片没有「选中」概念，
  用户的实际操作就是先复制）。代价是很久以前复制的图也可能被带上——chip 上会明示，可一键移除。
- 模拟 ⌘C 会**覆盖你的剪贴板**（翻译功能一直如此）。
- 不是所有模型都支持看图；选了纯文本模型会收到接口报错。
- 录音最长 60 秒自动结束，防止「松开」事件丢失导致麦克风一直开着。

## 已知限制

- 无自动化测试。
- 应用未做 Developer ID 签名 / 公证，仅适合本机自用。
- `NSAccessibility` 权限：**只有翻译**读取选中文本需要授予「辅助功能」权限，首次使用时按提示在
  「系统设置 ▸ 隐私与安全性 ▸ 辅助功能」中勾选 KoK。**快速问答不需要该权限。**
- 部分 OpenAI 兼容服务不支持 `stream`，此时会自动降级为一次性返回；若仍失败，面板会显示
  可重试的错误条。
